Map of Functions — Backtrail

Extensão VS Code que mantém histórico contínuo de arquivos em pastas sem git — captura cada save, exibe diffs e restaura versões sem sobrescrever os arquivos originais. MoF dividido por domínio desde v0.9.0 — este diagrama agrega os cinco arquivos em docs/mof/; ver docs/MOF.md para o índice textual.

Impact Rules

IDTriggerChangeAffected directAffected indirectRiskRecommended actions
IR_001F_CAPTUREcontrato — formato do StoreIndex/index.json ou SnapshotVersionF_STORE_QUERY, F_PRUNEF_WATCH, F_BASELINE, F_HISTORY_VIEW, F_CHANGES_VIEW, F_DECORATE, F_SEEN, F_DIFF, F_RESTORE altoÍndices existentes no disco dos usuários NÃO são migráveis automaticamente — qualquer mudança de schema exige migração ou leitura retrocompatível em readIndex; atualizar test/unit/snapshotStore.test.ts e revisar todos os testes de provider; mesmo princípio se aplica ao formato de blob (ver ADR-0001)
IR_002F_STORE_QUERYcomportamento — semântica de 'série ativa' (última versão define relPath; primeiro match vence)F_WATCH, F_BASELINE, F_DECORATE, F_CHANGES_VIEW, F_HISTORY_VIEW, F_SEENF_DIFF, F_OPEN_CHANGE altoÉ o maior fan-in do sistema — mudar a regra altera qual histórico cada arquivo mostra e qual série recebe o próximo snapshot; rodar test:unit e test:integration completos, revisar W_EDIT e W_RENAME de ponta a ponta
IR_005F_REGISTRYcontrato — chave backtrail.trackedFolders ou formato (string[] de caminhos absolutos)F_ACTIVATE, F_TRACK_FOLDER, F_UNTRACK_FOLDER, F_DECORATE, F_SEEN, F_HISTORY_VIEW, F_CHANGES_VIEW, F_TRACKED_VIEWtodas as demais — sem registro não há sistema altoFormato persiste entre sessões; migração obrigatória se mudar
IR_006F_PRUNEcomportamento — critério de descarte ou GC de blobsF_STORE_QUERYF_DIFF, F_RESTORE (blob removido = diff/restore quebrado) altoÚnica função que apaga dados PARCIALMENTE — teste de regressão obrigatório para qualquer mudança; GC só remove blob sem referência remanescente; roda com mais frequência desde a Fase 2 (setInterval diário + comando manual); cap por versão (maxVersionsPerSeries) desde a Fase 3
IR_011F_DELETE_BUCKETcomportamento — critério de quando apagar (quem confirma, quem não confirma)F_UNTRACK_FOLDER, F_TRACK_LIFECYCLEF_STORE_QUERY (bucket some inteiro, não parcialmente) altoApaga o bucket INTEIRO, irreversível, sem lixeira — teste de regressão obrigatório; preservar a assimetria de confirmação (Stop Tracking manual pergunta antes; untrackAndForget do cancelamento de baseline apaga sem perguntar)
IR_014F_PURGE_PATHcomportamento — critério de qual série é purgada, ou GC de blobsF_STORE_QUERY, F_STOP_TRACKING_PATHF_DIFF, F_RESTORE (blob removido = diff/restore quebrado) altoTerceira função que apaga dados do store — irreversível, sem teste de regressão não se mexe aqui; critério de match deve seguir a mesma regra de 'série ativa' de IR_002; GC de blob órfão deve usar o mesmo critério de referência de F_PRUNE
IR_003F_CAPTUREregra de negócio — dedup de saves (mesmo hash + mesmo relPath = mesma versão)F_WATCH, F_BASELINEF_HISTORY_VIEW (versões duplicadas), F_CHANGES_VIEW, F_RENAME_CORRELATION (rename de conteúdo idêntico depende de GERAR entrada) médioCuidado com a exceção do rename: conteúdo igual com relPath diferente PRECISA gerar versão — é o único registro do rename
IR_004F_SEENcontrato — chave backtrail.seenVersions ou formato do mapa seriesId→timestampF_DECORATE, F_CHANGES_VIEW, F_OPEN_CHANGEF_ACTIVATE (mark-seen do editor ativo) médioEstado persiste no globalState dos usuários — mudança de formato zera o 'visto' de todo mundo; comparação lexicográfica de timestamp exige manter toISOString (UTC)
IR_007F_IGNOREcomportamento — regra de matching (segmento exato, extensão, tamanho)F_WATCH, F_BASELINEvolume do store (ignorar de menos infla blobs; de mais perde histórico) médioAtualizar test/unit/ignoreFilters.test.ts; lembrar que config só é relida na criação do watcher
IR_008F_TRACK_LIFECYCLEcomportamento — semântica dos callbacks onFolderTracked/onFolderUntracked/onCaptureF_ACTIVATE, F_TRACK_FOLDER, F_UNTRACK_FOLDER, F_WATCHF_HISTORY_VIEW, F_CHANGES_VIEW, F_TRACKED_VIEW, F_DECORATE, F_BASELINE médioOrdem importa: watcher inicia ANTES do baseline; persistir rastreio ANTES de updateWorkspaceFolders; cancelamento do baseline desfaz o rastreio inteiro — preservar essa semântica
IR_012F_STORE_QUERYcomportamento — estratégia de cache/invalidação do índice em memória (indexCache, readMutableIndex)F_CAPTURE, F_PRUNEF_WATCH, F_BASELINE, F_DECORATE, F_HISTORY_VIEW, F_CHANGES_VIEW, F_SEEN médioCaminhos de escrita DEVEM usar readMutableIndex, nunca o índice de readIndex diretamente; cache é keyed pelo mtime do index.json; rodar test/unit/snapshotStore.test.ts a cada mudança nesta área
IR_015F_EXCLUDED_PATHScontrato — chave backtrail.excludedPaths ou formato (Record<folder, relPath[]>)F_IGNORE, F_MONITOR_VIEW, F_STOP_TRACKING_PATHF_WATCH, F_BASELINE (via getIgnoreConfigForFolder) médioFormato persiste entre sessões; migração obrigatória se mudar; atualizar test/unit/excludedPaths.test.ts e test/unit/ignoreFilters.test.ts
IR_009F_RENAME_CORRELATIONcomportamento — janelas de tempo (5000/500ms) ou critério de match por hashF_WATCHF_HISTORY_VIEW (histórico quebrado em duas séries), F_CHANGES_VIEW (arquivo renomeado aparece como New) baixoFalha de correlação não perde dados, só quebra a continuidade da série; atualizar test/unit/renameCorrelation.test.ts e fileWatcher.test.ts
IR_010F_DIFF_ELIGIBILITYcomportamento — conjunto de extensões de imagem ou regra binário/textoF_HISTORY_VIEW, F_CHANGES_VIEWF_DIFF (recebe versões que assume exibíveis) baixoAtualizar test/unit/diffEligibility.test.ts
IR_013F_WATCHcomportamento — introduz debounce de captura (captureDebounceSeconds) para relPath com série já ativaF_TRACK_LIFECYCLEF_HISTORY_VIEW (nova versão só aparece após o quiet window), F_CHANGES_VIEW (badge Modified atrasa até a captura disparar), F_DECORATE baixoEscopo restrito ao branch existingSeriesId, não estender sem reavaliar a correlação com IR_009; timer deve ser limpo no dispose junto com os de pending-deletion/grace; suítes que testam captura imediata usam captureDebounceSeconds: 0

Functions

IDNameDomainRiskResponsibilities
F_ACTIVATEAtivar e Orquestrar ExtensãoRastreamento —Instanciar e registrar as três tree views, o decoration provider e todos os comandos; criar o output channel "Backtrail" e um logWarning repassado a F_TRACK_LIFECYCLE; rodar prune de retenção periodicamente e sob demanda; instanciar F_TRACK_LIFECYCLE e conectá-la aos comandos; iniciar o watch de toda pasta persistida na ativação; marcar arquivo ativo como visto a cada troca de editor
F_TRACK_LIFECYCLEGerenciar Ciclo de Vida de Pastas RastreadasRastreamento médioIniciar/parar o watcher de uma pasta, incluindo hardening de permissões e prune de retenção antes do primeiro watch; orquestrar onFolderTracked (persistir bucketId, iniciar watcher, refrescar views, baseline cancelável); orquestrar onFolderUntracked e untrackAndForget; reiniciar o watcher de uma pasta quando um caminho é excluído; expor dispose() que encerra todos os watchers ativos
F_REGISTRYRegistro de Pastas RastreadasRastreamento altoListar, adicionar e remover pastas rastreadas persistidas em globalState; resolver se um caminho absoluto pertence a alguma pasta rastreada; filtrar entradas corrompidas defensivamente; persistir e recuperar o bucketId de cada pasta
F_EXCLUDED_PATHSRegistro de Caminhos Excluídos por PastaRastreamento médioListar, adicionar e remover caminhos relativos excluídos, por pasta rastreada, em globalState
F_TRACK_FOLDERRastrear PastaRastreamento —Comandos backtrail.trackFolder, backtrail.addFolder e backtrail.addFolderByPath; bloquear pastas dentro de repositório git; confirmar em modal quando a pasta é o home inteiro do usuário; persistir o rastreio ANTES de mexer no workspace; anexar a pasta ao workspace sem substituir pastas existentes
F_UNTRACK_FOLDERParar de Rastrear PastaRastreamento —Comando backtrail.untrackFolder: remover do registro, parar watcher, oferecer remoção da pasta do Explorer; variante untrackAndForget usada quando o usuário cancela o baseline
F_STOP_TRACKING_PATHParar de Rastrear um CaminhoRastreamento —Comando backtrail.stopTrackingPath e handler de checkbox da view Monitor: excluir um relPath e oferecer purgar seu histórico já salvo; reiniciar o watcher só da pasta afetada após excluir
F_GIT_GUARDBloquear Pastas em Repositório GitRastreamento —Detectar se um caminho está dentro de um repositório git subindo a árvore até a raiz procurando .git
F_WATCHVigiar Pasta RastreadaCaptura baixoCriar FileSystemWatcher por pasta rastreada e capturar snapshot a cada create/change não ignorado; registrar deleções como pendentes para correlação de rename; aplicar janela de graça de 500ms; debounce de 15s para saves consecutivos de relPath com série ativa; notificar consumidores via callback onCapture
F_BASELINECapturar Baseline de Pasta Recém-RastreadaCaptura —Percorrer a árvore da pasta e capturar o estado atual de cada arquivo não ignorado como primeira versão; trabalhar em chunks de 200 arquivos cedendo o event loop entre chunks; respeitar token de cancelamento e pular arquivos com série já ativa
F_RENAME_CORRELATIONCorrelacionar RenomeaçõesCaptura baixoCasar um create com uma deleção pendente de mesmo contentHash para manter a mesma série; escolher a deleção mais recente quando várias têm o mesmo hash
F_IGNOREFiltrar Arquivos IgnoradosCaptura médioDecidir se um relPath deve ser ignorado por tamanho, pasta, nome, extensão ou caminho excluído; ler configuração do usuário com defaults (node_modules, .git, dist, .env, etc.)
F_BINARYDetectar Conteúdo BinárioCaptura —Classificar conteúdo como binário se houver byte nulo nos primeiros 8000 bytes (mesma heurística do git)
F_CAPTURERegistrar Snapshot no StoreArmazenamento altoAnexar versão a uma série no index.json e gravar blob endereçado por sha256; deduplicar saves redundantes (conteúdo e relPath idênticos ao topo da série); variante batch para leitura/escrita única em N capturas
F_STORE_QUERYConsultar Histórico do StoreArmazenamento altoListar versões de uma série, ler conteúdo de blob, achar série ativa por relPath, listar arquivos ativos de uma pasta; getActiveSeries resolve série ativa + histórico numa única chamada
F_PRUNEAplicar Retenção de SnapshotsArmazenamento altoDescartar versões mais antigas que retentionDays, remover séries vazias e coletar blobs órfãos; aplicar cap de versões por série (default 100) após o filtro de idade
F_DELETE_BUCKETApagar Histórico Completo de uma PastaArmazenamento altoRemover o bucket inteiro (index.json, .bak, blobs/) de uma pasta rastreada; deleteBucketById apaga por id direto quando a pasta já não existe no disco
F_PURGE_PATHPurgar Histórico Sob um Caminho ExcluídoArmazenamento altoRemover retroativamente as séries cujo relPath ativo cai sob um prefixo de caminho, e fazer GC dos blobs órfãos
F_DIFF_ELIGIBILITYDecidir Elegibilidade de DiffVisualização baixoTexto sempre pode diff; binário só se for imagem (VS Code tem diff nativo de imagem)
F_HISTORY_VIEWExibir Histórico do Arquivo AtivoVisualização —TreeView backtrail.history: listar versões do arquivo do editor ativo; clique abre diff ou info conforme elegibilidade; re-renderizar em troca de editor ativo e em captura
F_CHANGES_VIEWExibir Mudanças Não VistasVisualização —TreeView backtrail.changes: agrupar arquivos ativos por estado (Modified acima de New); clique dispara abertura com par (anterior, atual); tolerar pasta rastreada inacessível sem quebrar a lista das demais
F_TRACKED_VIEWExibir Pastas RastreadasVisualização —TreeView backtrail.trackedFolders: listar pastas rastreadas com context menu (Stop Tracking, Mark All Seen)
F_MONITOR_VIEWExibir e Alternar Exclusão de CaminhosVisualização —TreeView backtrail.monitor: árvore por pasta rastreada espelhando o filesystem real; checkbox por nó refletindo se o relPath está excluído direto ou por herança
F_DECORATEDecorar Arquivos no ExplorerVisualização —FileDecorationProvider: badge N (novo) ou M (mudou) em arquivos de pastas rastreadas, com propagate para pastas pais; expor refresh(uri) e refreshAll()
F_SEENGerenciar Estado Visto/Não-VistoVisualização médioPersistir seriesId → último timestamp visto e derivar estado (new/changed/none); markManySeen aplica N entradas com uma única leitura/escrita; markFileAsSeen e markFolderAsSeen
F_DIFFMostrar Diff entre VersõesVisualização —Comando backtrail.showDiff: materializar os dois lados em tmpdir e abrir vscode.diff; comando backtrail.showVersionInfo para binários sem diff; limpar o tmpdir inteiro no dispose
F_OPEN_CHANGEAbrir Mudança da Lista de ChangesVisualização —Comando backtrail.openChangedFile: rotear para diff ou info, marcar a série como vista explicitamente e refrescar decoração + lista
F_RESTORERestaurar VersãoRestauração —Comando backtrail.restoreVersion: ler blob e gravar cópia em {pasta}/restored/... sem NUNCA sobrescrever o original; resolver colisões com sufixo incremental; slugificar segmentos de pasta
